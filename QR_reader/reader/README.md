# QR_reader — контроль выхода

Сайт читает QR-коды, созданные кабинетом классного руководителя, и погашает пропуск после успешной проверки в общей Google Таблице. Исходники находятся в ветке QR_reader. Публичная копия размещается в каталоге QR_reader ветки main.

## Подключение Google

1. Скачайте [ZIP с обработчиком этой ветки](https://github.com/ivangusarov386-lab/---/raw/refs/heads/QR_reader/integration/apps-script.zip) и откройте Code.gs в текстовом редакторе.
2. Замените полный код в вашем Google Apps Script и сохраните. Перевод страницы браузером должен быть отключён.
3. Обновите существующее развертывание через **Управление развертываниями → Изменить → Новая версия → Развернуть**.
4. Откройте сайт сканера. Адрес существующего веб-приложения /exec уже задан.

Обработчик совместим с кабинетом учителя, all_class и фоновой очисткой через 30 минут после назначенного выхода. Столбцы usedAt и useOperationId добавляются в лист «Пропуска» автоматически при первом погашении.

## Работа

**Камера.** Нажмите «Включить камеру» и разрешите доступ. После считывания QR камера останавливается, а сайт отправляет запрос погашения. Подтверждённый результат показывает имя ученика, класс, назначенное время выхода и время погашения. Для следующего ученика нажмите «Сканировать следующий».

**Поиск.** Введите часть ФИО в любом порядке. Поиск учитывает е/ё и регистр. В списке отображаются действующие непогашенные пропуска. Выберите запись и нажмите «Погасить пропуск» в окне подтверждения.

Погашенный пропуск сразу исключается из выдачи API для ученика и поиска. Повторное сканирование с другого устройства или новая проверка на том же устройстве получает отказ.

При обрыве связи кнопка «Повторить отправку» использует исходный ID операции. Тот же ID сохраняется в sessionStorage для восстановления после перезагрузки вкладки. Подтверждение одной завершённой операции возвращает исходный результат. Новый ID операции для погашенного пропуска отклоняется.

Отметка о погашении хранится в исходной строке до автоматического удаления по сроку. Сохранённые QR-поля и UUID пропуска используются при проверке. Поддельные данные с чужим ID отклоняются.

## Запуск сайта

Это статический сайт. В корне ветки находятся index.html, reader/app.js, reader/style.css и локальная библиотека vendor/jsQR-1.4.0.js.

Для локальной разработки выполните в корне ветки следующую команду.

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://localhost:8080. Камера работает в защищённом контексте HTTPS и на localhost. На телефоне используйте опубликованный HTTPS-адрес. Если доступ к камере запрещён, доступен поиск по ФИО.

Для публичной копии на существующем GitHub Pages файлы сайта копируются в каталог main/QR_reader с сохранением относительных путей reader и vendor.

## API

Запросы отправляются POST с JSON в теле и Content-Type text/plain;charset=UTF-8.

```json
{"action":"searchPasses","query":"Александров Артем"}
```

```json
{
  "action":"consumePass",
  "operationId":"bd84ad56-900c-4d30-90c3-dc5674993911",
  "passId":"d4f0378c-8f03-46f5-8e8c-68d74e61db3a"
}
```

Для сканирования добавляется строка qrPayload с полным исходным JSON QR-кода. Все девять полей QR сравниваются с выданным пропуском. Погашение выполняется под общей ScriptLock, используемой созданием и очисткой пропусков.

Успешный ответ содержит pass и consumption с operationId и usedAt. Ошибка содержит ok=false, code и error. Поддерживаются PASS_USED, PASS_EXPIRED, PASS_NOT_FOUND и PASS_MISMATCH.

В текущей демонстрации доступ к обработчику открыт по адресу веб-приложения. Данные 25 учеников вымышленные.

## Проверки

```sh
node --test tests/pass-api.test.cjs
```

Проверки покрывают поиск, погашение, повторный вход, поддельный QR, истечение срока, блокировку, повтор после потери ответа и совместимость с выдачей пропусков. Браузерный сценарий проверяет декодирование QR из синтетического видеопотока, ручное подтверждение, остановку камеры и восстановление незавершённой проверки.
