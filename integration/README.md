# Подключение пропусков к Google Таблице

Кабинет записывает пропуск в Google Таблицу и показывает QR после подтверждения записи. Запись связана с учеником через постоянный числовой `studentId`, а конкретный пропуск имеет уникальный `id`. Повторная отправка одного ID возвращает ту же запись.

Подключение подготовлено для [вашей таблицы](https://docs.google.com/spreadsheets/d/1YXDgWlNFhS4ONq7qlo33HgIgG4rYoFKYmotsLh5cxnY/edit). В ней нужны листы «Ученики» и «Пропуска», импортированные из Excel.

## Однократная настройка в Google

1. Откройте таблицу и выберите **Расширения → Apps Script**.
2. Скопируйте весь [Code.gs](Code.gs) в редактор скрипта и сохраните проект.
3. Выберите функцию **setupIntegration** и нажмите **Выполнить**. Подтвердите запрошенный доступ к вашей таблице. Скрипт проверит заголовки, задаст московский часовой пояс и покажет ключ учителя в окне таблицы. Повторный запуск покажет тот же ключ.
4. Нажмите **Развернуть → Новое развертывание → Веб-приложение**. Укажите выполнение **от вашего имени**, доступ **Все**, затем разверните. Для записи обработчик проверяет ключ учителя. Если администратор Google Workspace ограничил вариант «Все», понадобится разрешённый организацией способ публикации.
5. Скопируйте адрес веб-приложения, заканчивающийся на `/exec`.
6. В кабинете откройте **Панель → Пропуск → Настройки подключения**, введите адрес и ключ. Нажмите **Подключить таблицу**. При успешном ответе загрузится список учеников из листа «Ученики».

Ключ вводите в поле пароля кабинета. Он хранится в памяти страницы и sessionStorage до завершения сеанса вкладки. Адрес обработчика сохраняется в localStorage. Ключ в Google хранится в свойствах проекта Apps Script. Адрес Google Таблицы уже указан в Code.gs.

После изменения Code.gs обновляйте развертывание через **Развернуть → Управление развертываниями → Изменить → Новая версия**. Сохранение исходного кода и публикация новой версии выполняются отдельно.

## Проверка живого подключения

1. Выберите ученика, нажмите «Выдать пропуск», задайте дату и время и нажмите «Создать».
2. Дождитесь сообщения «Пропуск сохранён в таблице» и QR-кода.
3. На листе «Пропуска» появится строка с ID ученика, временем выхода и `qrPayload`.
4. Сканирование QR должно дать тот же JSON, который сохранён в `qrPayload`.

При ошибке сети повторите создание с теми же датой и временем. Кабинет сохраняет ID неподтверждённой отправки в sessionStorage. Обработчик проверяет ID под блокировкой и возвращает существующую запись при повторе. Другой набор данных с уже использованным ID отклоняется.

После перезагрузки страницы снова нажмите «Подключить таблицу». Адрес и ключ из текущего сеанса подставляются при подключении. Список учеников загружается заново.

## Формат обмена

Запросы отправляются методом POST в формате JSON с `Content-Type: text/plain;charset=UTF-8`. Такой тип позволяет браузеру выполнить простой междоменный запрос к Apps Script. Кабинет читает JSON-подтверждение от обработчика.

| Операция | Тело запроса | Ответ |
| --- | --- | --- |
| Список учеников | `{action: "students", teacherKey: "..."}` | `{ok: true, students: [{studentId, studentName, className}]}` |
| Запись пропуска | `{action: "createPass", teacherKey: "...", pass: {...}}` | `{ok: true, pass: {...}}` |
| Ошибка | | `{ok: false, error: "..."}` |

Состав `pass` совпадает с JSON внутри QR.

```json
{
  "version": 1,
  "type": "school-exit-pass",
  "id": "d4f0378c-8f03-46f5-8e8c-68d74e61db3a",
  "studentId": 1,
  "studentName": "Александров Артём",
  "className": "9А",
  "exitAt": "2026-11-27T14:30:00+03:00",
  "timeZone": "Europe/Moscow",
  "createdAt": "2026-11-26T18:00:00.000Z"
}
```

Обработчик проверяет ученика по справочнику, дату и формат данных, сохраняет пропуск одной строкой и возвращает подтверждение. Обязательные заголовки листа «Пропуска» соответствуют Excel. Порядок столбцов может изменяться.

```text
id, studentId, studentName, className, exitDate, exitTime,
exitAt, timeZone, createdAt, version, type, qrPayload
```

Значения `exitDate` и `exitTime` записываются из `exitAt`. Для QR используется JSON из `qrPayload`. Дата и время отображаются по Москве.

## Подключение all_class

Эта часть реализует запись из кабинета учителя в общую таблицу. Для доставки в интерфейс ученика в ветке Demo1 предстоит добавить выбор ученика и чтение его строк по `studentId` и `className`. Ключ учителя предназначен для кабинета с правом записи. Для интерфейса ученика потребуется отдельный способ чтения и идентификации.

## Локальная проверка обработчика

В корне репозитория выполните `node --test tests/pass-api.test.cjs`. Проверки используют модель Google Sheets и подтверждают запись, проверку ключа, валидацию, повторные запросы и восстановление после обрыва подтверждения. Живой доступ к Google проверяется после развертывания.
