# Подключение пропусков к Google Таблице

Кабинет записывает пропуск в Google Таблицу и показывает QR после подтверждения записи. Запись связана с учеником через постоянный числовой `studentId`, а конкретный пропуск имеет уникальный `id`. Повторная отправка одного ID возвращает ту же запись.

Подключение подготовлено для [вашей таблицы](https://docs.google.com/spreadsheets/d/1YXDgWlNFhS4ONq7qlo33HgIgG4rYoFKYmotsLh5cxnY/edit). В ней нужны листы «Ученики» и «Пропуска», импортированные из Excel.

## Скачивание исходника

[Скачайте ZIP с полным Code.gs](apps-script.zip), распакуйте и откройте Code.gs в Блокноте или редакторе кода. Скопируйте весь текст оттуда в Google Apps Script.

Отключите перевод страницы браузером на GitHub и в редакторе Google Apps Script. Автоматический перевод меняет имена JavaScript, строковые значения и названия листов. Например, typeof должно остаться typeof, result.warnings — result.warnings, а лист таблицы называется «Пропуска».

Файл в ZIP побайтово совпадает с integration/Code.gs. Его синтаксис и проверки обработчика проверены.

## Обновление существующего обработчика

1. Откройте таблицу и выберите **Расширения → Apps Script**.
2. Замените содержимое редактора полным текстом [Code.gs](Code.gs) и сохраните.
3. Выберите **Развернуть → Управление развертываниями → Изменить → Новая версия → Развернуть**. Адрес текущего веб-приложения сохраняется.
4. Откройте в кабинете **Панель → Пропуск**. Сайт автоматически подключится к сохранённому адресу и загрузит учеников.

Настройка через функцию setupIntegration удалена. Доступ для этой демонстрации открыт по адресу веб-приложения. Любой, у кого есть адрес, может получить список учеников и создать пропуск. В таблице используются вымышленные ученики.

Часовой пояс таблицы задаётся при записи пропуска. Адрес текущего обработчика задан в сайте и подставляется на новых устройствах. Для другого обработчика можно указать адрес в настройках подключения раздела «Пропуск».

## Первое развертывание

В редакторе Google Apps Script выберите **Развернуть → Новое развертывание → Веб-приложение**. Укажите выполнение **от вашего имени**, доступ **Все**, затем разверните. Если Google запросит разрешения, подтвердите доступ к таблице.

Скопируйте адрес веб-приложения, заканчивающийся на `/exec`. В кабинете откройте **Панель → Пропуск → Настройки подключения**, введите адрес и нажмите **Подключить таблицу**. Адрес сохраняется в localStorage этого устройства.

## Проверка живого подключения

1. Выберите ученика, нажмите «Выдать пропуск», задайте дату и время и нажмите «Создать».
2. Дождитесь сообщения «Пропуск сохранён в таблице» и QR-кода.
3. На листе «Пропуска» появится строка с ID ученика, временем выхода и `qrPayload`.
4. Сканирование QR должно дать тот же JSON, который сохранён в `qrPayload`.

При ошибке сети повторите создание с теми же датой и временем. Кабинет сохраняет ID неподтверждённой отправки в sessionStorage. Обработчик проверяет ID под блокировкой и возвращает существующую запись при повторе. Другой набор данных с уже использованным ID отклоняется.

После перезагрузки при открытии раздела «Пропуск» сайт подключается автоматически. При сетевой ошибке повторите подключение через настройки.

## Формат обмена

Запросы отправляются методом POST в формате JSON с `Content-Type: text/plain;charset=UTF-8`. Такой тип позволяет браузеру выполнить простой междоменный запрос к Apps Script. Кабинет читает JSON-подтверждение от обработчика.

| Операция | Тело запроса | Ответ |
| --- | --- | --- |
| Список учеников | `{action: "students"}` | `{ok: true, students: [{studentId, studentName, className}]}` |
| Пропуска ученика | `{action: "studentPasses", studentId: 1, className: "9А"}` | `{ok: true, passes: [{...pass, exitDate, exitTime, qrPayload}]}` |
| Запись пропуска | `{action: "createPass", pass: {...}}` | `{ok: true, pass: {...}}` |
| Ошибка | | `{ok: false, error: "..."}` |

Состав `pass` совпадает с JSON внутри QR.

```json
{
  "version": 1,
  "type": "school-exit-pass",
  "id": "d4f0378c-8f03-46f5-8e8c-68d74e61db3a",
  "studentId": 1,
  "studentName": "Александров Артём",
  "className": "9А",
  "exitAt": "2026-11-27T14:30:00+03:00",
  "timeZone": "Europe/Moscow",
  "createdAt": "2026-11-26T18:00:00.000Z"
}
```

Обработчик проверяет ученика по справочнику, дату и формат данных, сохраняет пропуск одной строкой и возвращает подтверждение. Обязательные заголовки листа «Пропуска» соответствуют Excel. Порядок столбцов может изменяться.

```text
id, studentId, studentName, className, exitDate, exitTime,
exitAt, timeZone, createdAt, version, type, qrPayload
```

Значения `exitDate` и `exitTime` записываются из `exitAt`. Для QR используется JSON из `qrPayload`. Дата и время отображаются по Москве.

## Подключение all_class

Обработчик поддерживает кабинет учителя и раздел «Пропуски» в текущей ветке Demo1. Кабинет вызывает `createPass`, приложение ученика вызывает `studentPasses` с числовым `studentId` и точным `className`.

В ответе возвращаются исходный ID, все поля QR, исходная строка `qrPayload`, дата и время выхода по Москве. Фильтрация выполняется по ID и классу одновременно. Пустой список возвращается как `{ok: true, passes: []}`. Новые пропуска идут первыми по дате выхода. Доступ в этой демонстрации открыт по адресу обработчика.

После замены кода опубликуйте новую версию существующего развертывания. В all_class выберите класс 9А и ученика из списка, затем откройте «Пропуски». Приложение обновляет записи каждые 15 секунд, пока раздел открыт.

## Локальная проверка обработчика

В корне репозитория выполните `node --test tests/pass-api.test.cjs`. Проверки используют модель Google Sheets и подтверждают запись, отклонение некорректных запросов, валидацию, повторные запросы и восстановление после обрыва подтверждения. Живой доступ к Google проверяется после развертывания.

## Чтение пропусков учеником (All-Class)

В `Code.gs` добавлена read-only операция `studentPasses`. Операции `students` и
`createPass`, блокировка записи и повторная отправка учителем сохранены.

```json
{"action":"studentPasses","studentId":1,"className":"9А"}
```

Отправляйте POST на существующий `/exec` с `Content-Type: text/plain;charset=UTF-8`
(тело содержит JSON; этот MIME-тип не вызывает CORS preflight в Google Apps Script).
Ключи и cookies не требуются. Пример успешного ответа:

```json
{
  "ok": true,
  "passes": [
    {
      "version": 1,
      "type": "school-exit-pass",
      "id": "d4f0378c-8f03-46f5-8e8c-68d74e61db3a",
      "studentId": 1,
      "studentName": "Александров Артём",
      "className": "9А",
      "exitAt": "2026-11-27T14:30:00+03:00",
      "timeZone": "Europe/Moscow",
      "createdAt": "2026-11-26T18:00:00.000Z",
      "qrPayload": "{\"version\":1,\"type\":\"school-exit-pass\",\"id\":\"d4f0378c-8f03-46f5-8e8c-68d74e61db3a\",\"studentId\":1,\"studentName\":\"Александров Артём\",\"className\":\"9А\",\"exitAt\":\"2026-11-27T14:30:00+03:00\",\"timeZone\":\"Europe/Moscow\",\"createdAt\":\"2026-11-26T18:00:00.000Z\"}",
      "exitDate": "2026-11-27",
      "exitTime": "14:30"
    }
  ]
}
```

Без записей: `{"ok":true,"passes":[]}`. При ошибке: `{"ok":false,"error":"…"}`.
Проверяется существование **пары studentId + className** на листе «Ученики»;
строки «Пропуска» фильтруются по обоим значениям. Чужие/пустые строки не
разбираются. Повреждённые строки выбранного ученика исключаются из результата. В поле
`warnings` возвращаются их номера и пояснения, а корректные пропуска остаются доступными. Записи сортируются по времени выхода, новые первыми.

`qrPayload` возвращается **точной исходной строкой из ячейки**, включая порядок
полей и пробелы. Ученическое приложение кодирует эту строку байтами UTF-8 в QR,
не сериализуя JSON заново. UUID не изменяется. Время отображается в Europe/Moscow.
Чтение не создаёт, не изменяет и не удаляет пропуска.

### Важно: обновить живое развёртывание

Push в GitHub **не меняет опубликованный Apps Script**. После получения новой
версии `integration/Code.gs` выполните:

1. Откройте общую таблицу → **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` полным кодом из этого репозитория и сохраните.
3. **Развернуть → Управление развертываниями** → выберите существующее
   веб-приложение с используемым `/exec` → карандаш **Изменить**.
4. В поле версии выберите **Новая версия** → **Развернуть**. Выполнение от имени
   владельца; доступ **Все**. При запросе подтвердите доступ владельца к таблице.
5. Сохраните прежний адрес `/exec`; создавать новое развёртывание не нужно.
6. Проверьте POST `students` (текущие 25 вымышленных учеников в 9А), затем POST
   `studentPasses` для ID 1 и 9А. Ожидается `ok:true` и массив `passes`.
7. В кабинете учителя оформите пропуск выбранному ученику. В All-Class откройте
   «Пропуски» для него: запись должна появиться не позже следующего обновления
   (15 секунд плюс время запроса). Смените ученика — прежний QR должен исчезнуть.

До шага 4 живой адрес сообщает «Неизвестная операция.», а All-Class показывает
сообщение о необходимости обновить Apps Script. На момент разработки проверены
живое чтение `students` и отсутствие `studentPasses` в старом развёртывании;
сценарии новой операции проверяются локально в модели Google Sheets:

```sh
node --test tests/pass-api.test.cjs
```

Демонстрационный доступ без ключа предназначен для вымышленных данных. Выбор
ученика в All-Class не является авторизацией; ни сервер, ни клиент не ограничивают,
кто может выбрать другое имя. Для реальных персональных данных такой режим
не подходит. В текущей задаче новые аккаунты и авторизация не вводятся.


## Подтверждение записи и повреждённые строки

После выдачи кабинет повторно вызывает studentPasses и проверяет наличие того же ID и данных QR. Успешное сохранение показывает ссылку на конкретную строку Google Таблицы. Каждый новый пропуск добавляется в конец листа «Пропуска».

Ответ studentPasses включает rowNumber и sheetUrl у каждой корректной записи. Неполные старые строки перечисляются в warnings с полями rowNumber и message. Приложение ученика показывает предупреждение, сохраняя доступ к корректным пропускам. Чтение оставляет исходные строки таблицы как есть.

После изменения этого обработчика обновите существующее развёртывание Google Apps Script через новую версию. Публикация сайта из GitHub и публикация скрипта Google выполняются отдельно.
